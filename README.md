# Quick Dot Game

A minimalistic web-based reaction game where you have to click a dot before it disappears. The game gets progressively faster with each click!

This project was built using standard Web Technologies without any external frameworks or libraries. 

## Concepts Used

### HTML (HyperText Markup Language)
HTML provides the structure for the three screens (Start, Game, Game Over).

*   **`<!DOCTYPE html>` & `<html>`**: Defines the document as an HTML5 document.
*   **`<head>`**: Contains meta information like character encoding (`<meta charset="UTF-8">`), viewport settings for mobile responsiveness (`<meta name="viewport">`), and links to external files (`<link rel="stylesheet">`).
*   **`<body>`**: Contains the visible content of the page.
*   **`<div>`**: Used extensively as a container to group elements together, especially for structural layout (like `.modal` or `#game-area`).
*   **Text Tags (`<h1>`, `<p>`, `<span>`)**: `<h1>` is used for the main headings, `<p>` for paragraph text, and `<span>` to hold the dynamic score number so it can be targeted by JavaScript.
*   **`<button>`**: Interactive clickable elements to navigate between screens.
*   **`<script>`**: Used to link external JS files directly into the HTML to handle the game's logic.

### CSS (Cascading Style Sheets)
CSS is used to style the UI elements, position them, and create a modern dark theme.

*   **Selectors**: The code uses Element selectors (e.g. `body`, `button`), ID selectors (e.g. `#dot`, `#game-area`), and Class selectors (e.g. `.modal`) to target specific tags.
*   **Box Model**: Core sizing properties like `padding`, `margin`, `width`, and `height` dictate element boundaries.
*   **CSS Grid (`display: grid`)**: Used on the `body` to quickly center the contents of the page both vertically and horizontally (`place-items: center`).
*   **Absolute & Relative Positioning**: 
    *   `#game-area` is set to `position: relative` to act as an anchor limit.
    *   `#dot` is set to `position: absolute` so it can be freely moved around the screen using `top` and `left` coordinates generated by JS.
*   **Colors & Visuals**: Uses precise colors like `#1a1a2e` (background) and `#ffffff` (text/dot). Uses `border-radius: 50%` to make the dot a perfect circle. Uses `box-shadow` to give the white dot a glowing effect. Includes `rgba()` for a slightly transparent modal background.
*   **Interactivity (`:active` & `transition`)**: The `button:active` state is styled with `transform: scale(0.95)` and a `transition` to give a tactile "press down" animation effect when you click it.
*   **User Selection**: `user-select: none` stops accidental highlighting of text when clicking rapidly.

### JavaScript (JS)
JavaScript handles the core gameplay loop, randomization, and state management.

*   **Variables (`let`, `const`)**: Used to store the current `score`, the `time` limit, and the `timer` ID. `const` is used to hold a permanent reference to the dot element.
*   **DOM Manipulation**: `document.getElementById('dot')` is used to fetch the HTML element. `dot.style.display` and `dot.style.left` are used to directly inject CSS properties onto the element to hide/show and move it. `innerText` updates the visible score text.
*   **Event Listeners**: Functions are triggered via HTML event attributes (`onclick`, `onmousedown`). `onmousedown` is used on the dot instead of `onclick` for slightly faster response times.
*   **Event Object (`e.stopPropagation()`)**: Prevents the click event on the dot from bubbling up and triggering unintended clicks on other overlapping elements.
*   **Math Object**: `Math.random()` generates a random number used calculated with `window.innerWidth` and `window.innerHeight` to spawn the dot anywhere on the screen layout. `Math.max()` locks the shrinking `time` variable so it never drops below 350 milliseconds.
*   **Timers (`setTimeout`, `clearTimeout`)**: 
    *   `setTimeout` sets delayed actions—like making the dot change its position or triggering the Game Over screen after your `time` runs out.
    *   `clearTimeout` cancels the pending Game Over if you click the dot successfully, allowing the game loop to reset.
*   **Browser APIs (`location.href`, `localStorage`)**: 
    *   `location.href` redirects the user's browser between `index.html`, `game.html`, and `end.html`.
    *   `localStorage` persists the final `score` inside the browser's storage so that `end.html` can read it and display it after the redirect.
